# Cube Memory Seed 实验报告

## 1. 协议

- 每个规划周期按当前 9 维特权状态，从 1,760,000 个专家 anchor 中精确检索 10 个不同 source episode。
- 排除当前评估 episode；每个邻居提供连续 25 个环境动作。
- CEM 每轮保留 `candidate 0 = current mean`，并用同一组 memory seed 覆盖 slots 1–10；其余采样、10 轮更新、top-30 和最终 elite-mean 提取规则不变。
- 三个条件使用同一组 50 个冻结 env；12-env 结果只用于首周期机制诊断，不能当总体成功率。

## 2. 50-env 闭环结果

| 条件 | 原 mean 基线 | Memory Seed | 变化 | 失败→成功 | 成功→失败 |
|---|---:|---:|---:|---|---|
| Red | 36/50 = 72% | **44/50 = 88%** | **+16 pp** | 0, 1, 6, 26, 27, 34, 36, 38 | 无 |
| Blue-v2 | 32/50 = 64% | **34/50 = 68%** | **+4 pp** | 1, 6, 9, 26 | 10, 45 |
| Yellow-v2 | 31/50 = 62% | **33/50 = 66%** | **+4 pp** | 6, 9, 26, 29 | 42, 45 |

结论：生成层检索种子在 ID 红色下带来明确的 +16pp；在 Blue/Yellow v2 下均为净 +4pp，但各有两例反向翻转，因此 OOD 下不是逐样本单调改善。

## 3. 固定 12-env 首周期池审计

| 条件 | 未注入池有解 | 注入后池有解（ever/final） | Memory slots 有解（ever/final） | CEM mean 成功（ever/final） | 旧无解→新有解 env |
|---|---:|---:|---:|---:|---|
| Red | 8/12 | **12/12 / 11/12** | 10/12 / 9/12 | 9/12 / 9/12 | 0, 1, 6, 38 |
| Blue-v2 | 9/12 | **12/12 / 11/12** | 10/12 / 9/12 | 8/12 / 8/12 | 0, 1, 38 |
| Yellow-v2 | 8/12 | **11/12 / 11/12** | 10/12 / 9/12 | 7/12 / 7/12 | 0, 11, 38 |

注入后，Red/Blue 的 12 个池全部至少含一条曾成功轨迹，Yellow 为 11/12。三色 memory slots 本身均在 10/12 个 env 中包含曾成功轨迹；说明检索确实缓解了“生成池无解”。但 CEM mean 仍只选中 9/12、8/12、7/12，选择层仍是剩余瓶颈。

## 4. 证据完整性

- 三色共 150 个视频，逐帧解码均为 50 帧、736×288。
- 三色共 150 份 cost history；每周期均有 `(10,300)` cost 和最终 `(300,5,25)` population。
- 所有检索均为 10 个不同 source episode，未命中当前评估 episode；25 步动作未跨 episode。
- 正式日志均无 Traceback、RuntimeError、OOM 或进程异常退出。

本结果证明的是 privileged-state memory 的生成层机制价值，不代表已得到可部署的视觉检索器。
